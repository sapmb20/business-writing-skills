# Email and letter templates

Part of `email-writing`. Three fill-in templates: a request email, a follow-up, and a
full-block business letter.

> **Source and license.** Compiled for this repo (CC BY 4.0, see LICENSE-CONTENT). The
> wording is new; the structure follows published guidance, credited element by element in
> the "How this was compiled" table under each template. The main source is *Communication
> at Work* by Julie Rivers (eCampusOntario, 2022), sections 7.1 and 8.1,
> https://ecampusontario.pressbooks.pub/comm1062/, licensed
> [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Elements no source supports
> are marked "repo convention".

---

## 1. Request email

```
Subject: [Action + topic + date], e.g. "Approve Q3 travel budget by Fri, Oct 16"

Hi [First name],                       (or "Dear Ms. [Last name]," for a first contact)

[Main point in one or two sentences: what you need and by when.]

[Context in two or three sentences: only what the reader needs to say yes. Link or attach
the detail rather than pasting it. Several steps? Number them.]

Could you please [specific action] by [weekday, date]? [If it helps: "A yes by reply is
enough."]

[One line of thanks or goodwill.]

[Sign-off],
[Full name]
[Title, organization]
[Phone]
```

Before sending: one purpose per email; the ask has a verb, an owner (the reader), and a
date; the subject line would make sense in the reader's inbox a week from now. If you
expect resistance, don't open with the ask: use the indirect order (buffer, reasons, ask,
closing with the date), as in `delivering-bad-news`.

**How this was compiled**

| Element | Source |
| --- | --- |
| Subject line names the action; short | *Communication at Work* 8.1, Table 8.1.2 (a 3- to 7-word title) |
| Direct order: request first, then context, then the deadline | *Communication at Work* 8.1.2, Table 8.1.2 (opening, body, closing) |
| Numbered steps for multi-part requests; "please" | *Communication at Work* 8.1.2 |
| Indirect order when resistance is expected | *Communication at Work* 8.1.2 (indirect requests) |
| Date in the subject; one purpose per email | Repo convention (`email-writing`) |

## 2. Follow-up (no reply yet)

Send once, in the same thread, about a week after the first message.

```
Subject: (keep the original subject, so it stays in the thread)

Hi [First name],

Following up on my note below about [topic]. [Restate the ask in one line, with the date.]

[Optional: one new fact that makes it easier to answer, or a smaller ask: "Even a quick
'not now' would help me plan."]

Thanks,
[First name]
```

Don't send a third message in the same week; if it matters, call or ask someone else.

**How this was compiled.** No credible open source sets a follow-up interval, so the timing
("about a week", "not a third in the same week") is a **repo convention**. Change it to
your organization's norm. Keeping the reply in the thread follows *Communication at Work*
8.1.1: change the subject line only when the topic changes.

## 3. Full-block business letter

Every line starts at the left margin; no indents; single-spaced, with a blank line between
parts.

```
[Your organization's letterhead, or your street address
 City, ST ZIP]                                      (omit the name; it goes in the signature)

[Month D, YYYY]

[Recipient's full name, title]
[Organization]
[Street address]
[City, ST ZIP]

Re: [Subject, in bold]                               (optional)

Dear [Mr./Ms./Mx./Dr. Last name]:      (colon in formal letters; "Dear [Full name]:" when
                                        you're unsure of the title)

[Opening paragraph: the purpose, in the first sentence or two.]

[Body: the details, one topic per paragraph.]

[Closing paragraph: the action you want or will take, with a date; a line of goodwill.]

Sincerely,

[Handwritten signature]

[Full name], [Title]
[Organization]

Enclosures (2): [Document name], [Document name]
cc: [Name]
```

Use a letter for formal, external, or legal matters; for bad news, structure the body with
`delivering-bad-news` and its templates. Letter size, 1-inch margins, a standard serif or
sans-serif face.

**How this was compiled**

| Element | Source |
| --- | --- |
| The parts and their order (letterhead or return address, date, recipient address, subject reference, salutation, opening, body, closing, complimentary close, signature, signature block, enclosure notice) | *Communication at Work* 7.1.1-7.1.12 |
| Block style: everything flush left, blank line between paragraphs | *Communication at Work* 7.1, 7.1.7 |
| Date spelled out ("April 25, 2020") | *Communication at Work* 7.1.2 |
| "Dear [Title] [Name]:" with a colon; omit an uncertain title; Mx. | *Communication at Work* 7.1.5 |
| "Re:" subject line in bold | *Communication at Work* 7.1.4 |
| About three lines for a handwritten signature | *Communication at Work* 7.1.10 |
| Page: 8.5 × 11 in, 1-inch margins, standard face | *Communication at Work* 7.1.13 |
| US address lines: two-letter state abbreviation, ZIP Code | USPS, *Publication 28: Postal Addressing Standards* (Oct. 2024), https://pe.usps.com/text/pub28/welcome.htm (the source book uses Canadian address style) |
| "Enclosures (2):" and "cc:" lines | *Communication at Work* 7.1.12; cc is common US practice |
